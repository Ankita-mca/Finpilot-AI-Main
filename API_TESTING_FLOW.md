## 1. Executive Summary & Core Architectural Principles

Before executing any request in Postman, understand how the FinPilot AI architecture enforces security, multi-tenancy, and data integrity:

### A. Authentication & Session Architecture
* **Cookie-Based Sessions**: FinPilot does **NOT** use JWT `Bearer <token>` headers. Authentication is handled via Django session cookies (`sessionid`).
* **Session Lifecycle**: When you execute `POST /api/v1/auth/login/` or `POST /api/v1/auth/register/`, Django returns a `Set-Cookie: sessionid=...`. Postman's cookie jar automatically stores and forwards this cookie on all subsequent requests.
* **⚠️ The Logout Trap**: Do **NOT** test `POST /api/v1/auth/logout/` immediately after login! Logging out destroys the `sessionid`. If you log out in Step 5, all subsequent 82 API calls will fail with `401 Unauthorized` or `403 Forbidden`. **Logout must always be tested at the very end of your testing cycle**.

### B. CSRF Protection (Write Operations)
* Every mutating HTTP method (`POST`, `PUT`, `PATCH`, `DELETE`) requires a CSRF token.
* **Token Source**: `GET /api/v1/auth/csrf/` sets the `csrftoken` cookie.
* **Token Header**: Must be passed as `X-CSRFToken: {{csrf_token}}`. The test script in Postman automatically captures `csrftoken` into `{{csrf_token}}`.

### C. Multi-Tenancy via `X-Organization-ID`
* FinPilot enforces strict tenant isolation using the custom permission class `HasOrganizationAccess`.
* Every business endpoint inspects the incoming request for:
  1. Header `X-Organization-ID: {{organization_id}}`, OR
  2. Query parameter `?organization={{organization_id}}`.
* If this header is missing or references an organization where the authenticated user is not an active member, the API rejects the request with **HTTP 403 Forbidden**.
* Mutating operations additionally verify that the member role is one of `owner`, `manager`, or `accountant` (`WRITE_ROLES`).

### D. Financial Data Representation (Minor Units / Paise)
* All monetary amounts are stored and transmitted in **minor currency units (paise for INR)**:
  * ₹100.00 = `10000` paise
  * ₹1,500.50 = `150050` paise
* GST rates are stored in **basis points (bps)**:
  * 0% = `0` bps
  * 5% = `500` bps
  * 12% = `1200` bps
  * 18% = `1800` bps
  * 28% = `2800` bps

### E. ⚠️ The Invoice Void Trap
* In `core/views.py`, the `void` action checks:
  ```python
  active_allocs = invoice.allocations.filter(reversed_at__isnull=True)
  if active_allocs.exists():
      return Response({"detail": "Reverse existing allocations before voiding this invoice."}, status=400)
  ```
* If you void an invoice before recording payments, you cannot allocate payments to it.
* If you attempt to void an invoice that already has active payment allocations, the server returns **HTTP 400 Bad Request**.
* **Correct Testing Flow**: Invoices must be created -> Payments allocated -> Allocation reversed -> Invoice voided (or test void on a secondary header-only invoice).

## 5. Postman Operator Handbook

Follow this checklist for every individual request execution:

1. **Active Environment**: Check top right dropdown in Postman. It must read `FinPilot AI - Local Dev`.
2. **Auto-Populated Variables**: After Step 1 (`Get CSRF Token`), inspect your environment to confirm `csrf_token` has a value. After Step 4 (`Get Current User`), confirm `organization_id` has a value.
3. **Cookie Verification**: Click the **Cookies** link under the **Send** button in Postman to confirm `sessionid` and `csrftoken` exist for `127.0.0.1`.
4. **Header Checks**:
   - For write operations (`POST`, `PUT`, `PATCH`), confirm header `X-CSRFToken` is set to `{{csrf_token}}`.
   - For org-scoped operations, confirm header `X-Organization-ID` is set to `{{organization_id}}`.
5. **PASS Criteria**:
   - Status code matches table (e.g. `200 OK` or `201 Created`).
   - Postman Test Results tab shows `PASS` on all assertions.
   - Dynamic ID variables (`test_customer_id`, `test_invoice_id`, etc.) update in the active environment.
6. **FAIL Criteria**:
   - `401 Unauthorized`: Session cookie missing or expired. Re-run `03 - Login`.
   - `403 Forbidden`: Either CSRF token missing/mismatched, or `X-Organization-ID` missing/not a member.
   - `400 Bad Request`: Validation failure. Check response JSON `detail` or field error messages.
